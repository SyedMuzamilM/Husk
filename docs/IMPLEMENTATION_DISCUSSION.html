Verification
29 regression checks

Pass on Apple Silicon, macOS 27, Xcode 27, Swift 6.4. Debug/Release build; Thread and Address Sanitizer fixture suites pass. One benchmark test is opt-in.

Large pipe output, timeout/cancellation, mixed failures, stale identities, symlink swaps, hardlinks, host rights, descriptors, and model release are covered.

Local metadata benchmark
100k entries · ~32 MiB RSS

Per-entry autorelease pools reduced isolated-service peak RSS from ~518 MiB to ~32 MiB. Both runs visited every entry in ~7 seconds. Earlier 10k/100k metadata benchmarks completed in ~0.8/~8 seconds.

Empty-file fixtures on this APFS SSD. No real-world speed guarantee or leak-free claim.

Deliberately unavailable

Project deletion remains inspection-only until Git tracking and active builds can be verified. Whole AI histories/models/VMs, automatic deletion, permanent deletion, and privileged hardware control are excluded from routine cleanup.

Before source publication

License and ownership

Apache-2.0 is the suggested permissive option with an explicit patent grant. MIT is shorter. GPL-3.0 requires derivative distributions to remain under its terms. Mole's license does not decide Husk's license.

Before downloadable release

Distribution and support

Signing/notarization tooling is prepared. Configure Developer ID and notary credentials in the local keychain, enable private vulnerability reporting, and choose supported OS/hardware.

Keep secrets in the keychain. Do not enter keys or passwords here.

Next Mole-inspired work

1. Prove project cleanup safety

Associate cache folders with manifests and repositories. Exclude Git-tracked content, nested repos, modified dependencies, and active builds. Show project age and rebuild cost before enabling per-project deletion.

2. Separate models and histories from cache junk

Read model manifests and retention metadata locally. Preview model names, references, download cost, chats, and checkpoints. Let users review individual records and keep them out of Select Safe.

3. Add useful monitoring without constant work

Consider short CPU/memory charts, read-only port ownership, and an optional menu-bar view. Reuse measurements and stop sampling when no visible consumer needs it. Read-only MCP should come before any agent-triggered action.
